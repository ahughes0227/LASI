# Capability Development Capability

READ a typed capability request, semantic capability manifests, component
schemas, relevant architecture/policies, and dependency/evaluation evidence.

DO mandatory structural deduplication, choose REUSE/COMPOSE/EXTEND/NEW, isolate
the actual gap, construct minimum-sufficient build context, record source-backed
research decisions, freeze a build plan, create or revise only the authorized
fixed-shell package, and validate it.

WRITE resolution, research, build, test, evaluation, validation, and
registration-proposal artifacts. Do not execute generated code merely because
it was built. Do not register a shared capability without explicit
`update_toolbox` approval bound to the validated package hash.
